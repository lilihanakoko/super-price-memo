# スーパー価格メモ（第1段階 試作品）

値札にスマホを向けて商品名と価格を読み取り、その店舗での前回価格・最安値や他店舗の直近価格と比べる個人用PWAです。

## 推奨技術（第1段階）

| 項目 | 採用 | 理由 |
|---|---|---|
| アプリ形式 | PWA（HTML/CSS/JavaScript、ビルド不要） | Android・iPhone 両対応、ホーム画面から起動、無料で配信できる |
| カメラ | `getUserMedia` のライブ映像 | 写真撮影APIを使わないためシャッター音が出ない。アルバムにも保存されない |
| OCR | Tesseract.js 5.1.1（日本語、WebAssembly） | 端末内で処理、画像を外部へ送らない、無料 |
| バーコード | `BarcodeDetector`（対応端末のみ） | Android の Chrome で JAN を読める。非対応端末では無視 |
| 保存 | IndexedDB | 端末内に保存。アカウント・サーバー不要 |
| オフライン | Service Worker | 店舗選択・履歴・手入力はオフラインでも動く |
| 配信 | GitHub Pages（推奨）など無料の HTTPS ホスティング | カメラには HTTPS が必要 |

## 画面構成

- **店舗選択**（起動時）：前回の店舗を一番上に表示。追加・編集・削除、店舗ごとに「カメラ可／手入力のみ」
- **買い物メイン**：値札を読み取る／手入力・商品から選ぶ／今日なに作ろう？／材料リスト／価格履歴／設定
- **カメラ読み取り**：ライブ映像＋読み取り枠。価格候補の数字をチップで表示し、**どの数字を採用したか**を選べる。税込／税抜の切り替え、商品名の候補、内容量・JAN
- **商品情報**：名前・規格・価格の修正、既存商品との照合（容量違いは選ばないよう注意表示）、前回比・この店舗の最安値・他店舗の直近価格（記録日つき）、単価（100g・100ml・1個あたり）、価格を記録、材料リストに追加、AIにレシピを聞く、価格推移グラフ
- **価格履歴**：店舗・商品名で絞り込み、記録の修正・削除
- **材料リスト**：追加・名前の修正・削除・全消去、レシピ相談
- **設定**：店舗管理、OCRデータの事前準備、API設定（第3段階）、JSONバックアップ・復元

## 仕様の守り方（要点）

- カメラ映像のフレームは画面に表示しないメモリ上の canvas にだけ描き、認識後すぐ消去。保存・送信なし
- 認識結果は必ず確認画面を通してから保存。読み取りは「この内容で確認へ」を押すまで記録されない
- 同じ商品・同じ店舗・同じ価格を30分以内にもう一度記録しようとすると確認が出る（連続認識による重複防止）
- 比較は **税込価格** で行う。税抜しか読めなかった場合は警告を出し、×1.08／×1.10 ボタンで計算できる
- 本体価格と税込価格のペア（例：198円と213.84円）を見つけた場合は税込側を自動で採用
- 商品は利用者が選んだ場合だけ同一商品として扱う（JAN一致は候補の先頭に表示）。容量違いを自動で同一視しない
- 全国平均・値上げ情報・レビューは未実装のため「データなし／未対応」と表示（推測値は出さない）

## パソコンで動かす

```bash
python -m http.server 8765 --bind 127.0.0.1
```

ブラウザーで http://localhost:8765 を開きます（localhost ならカメラも使えます）。

## スマホで実機テストする

カメラは **HTTPS** でないと使えません。また、データは**URLごと**にブラウザーへ保存されるため、使い続けるURLを最初に決めてください（URLを変えると履歴が見えなくなります。その場合は JSON バックアップで移せます）。

**おすすめ：GitHub Pages（無料・HTTPS・URLが固定）**

1. GitHub に公開リポジトリを作り、このフォルダーの中身をアップロード
2. リポジトリの Settings → Pages → Branch を `main` / `/(root)` にして保存
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける
4. スマホで開き、ホーム画面に追加
   - iPhone：Safari の共有ボタン →「ホーム画面に追加」
   - Android：Chrome のメニュー →「ホーム画面に追加」／「アプリをインストール」

※ ソースは公開されますが、価格データは端末内にしかなく、APIキーも含まれていません。

**初回の準備**：設定 →「認識データを準備する」を Wi-Fi のある場所で押しておくと、売り場ですぐ読み取れます（日本語データ数MB）。

## 使い方のコツ

- 値札を枠いっぱいに入れ、手ぶれを抑えると精度が上がります。暗い売り場では 💡（対応端末のみ）
- 読み取り中に候補をタップすると自動で一時停止するので、落ち着いて選べます
- 読み取りが難しい値札は「カメラを使わず手入力」。登録済みの商品なら検索して価格だけ入力できます
- 店内でのカメラ使用は各店舗のルールに従ってください（店舗ごとに「手入力のみ」に設定できます）

## ファイル構成

```
index.html             画面の枠
style.css              スタイル（ダークモード対応）
js/app.js              画面・記録・比較・材料リスト・バックアップ
js/ocr.js              カメラ・OCR・値札の解析
js/db.js               IndexedDB
sw.js                  オフライン用 Service Worker
manifest.webmanifest   ホーム画面アプリ設定
icons/                 アイコン
```

更新を公開したら `sw.js` の `VERSION` を上げると、次回起動時に新しい版へ切り替わります。
